# Plan

> Historical plan from 26 September 2026. The active plan is
> [`docs/plan.md`](../plan.md); source scope and implementation order have
> since changed.

Order is value for a Perth pilot and kiteboarder who also watches Sydney, divided by effort, and cut by the terms in `sources.md`. v0 is the free, personal, non-GRIB set, and it stays at or under half the Open-Meteo daily and monthly caps (`budget.md`). Nothing here is a licence to scrape `www.bom.gov.au`, to call `api.weather.bom.gov.au`, or to pull NAIPS. The popover carries one line: “Situational awareness only — not a flight briefing”.

## v1 — after v0 has run for a week

Only what v0’s `status.json` shows a need for.

| Item | Why it waits |
| --- | --- |
| 06Z national grid | The kite and pilot points already update four times a day. Another 1,836 grid calls would put the daily total near 41% spare, under the 50% headroom rule. Reopen the rule before adding it. 18Z is the same size again. |
| RainViewer frames for Perth (`IDR`-equivalent view) and Sydney | Terms allow personal use with a RainViewer credit and no published numeric cap. Bureau radar stays out until `webreg@bom.gov.au` says otherwise. |
| GIBS Himawari band 13 tiles for the same two windows | The layer responded. Find the acknowledgement page before storing a year of tiles. The docs index 404’d. |
| A named marine model, if Best Match drifts | Pinning `ecmwf_wam` dropped sea-surface temperature on 26 Sep 2026. Revisit only with a live check that SST and `sea_level_height_msl` still fill. |
| GFS 0.25° at the two cities, not a second national grid | A freezing-level cross-check returned 2260 m against the IFS interpolation of 2362 m. Eight calls a day fit in the spare. Not required for v0. |
| Bureau tides | Only if a feed’s terms allow a personal daemon. The conditions PDF requires the Commonwealth disclaimer and does not authorise scraping. |
| Australian AIRMET | Only if a machine feed turns up whose terms allow it. The website pages and the US AIRMET endpoint do not. |
| Previous-run archive for the prognosis crossfade | Isobar already crossfades two issues. v0 keeps the last two local copies. A real back catalogue needs the Open-Meteo previous-runs API, which is on the free tier and off the Standard plan. |
| Catch-up metrics | If the Mac regularly misses a run, that is the signal to move the job to a small VPS. Price the VPS then; it was not on the page fetched in phase 1. |

Still no GRIB, no ACCESS-G, no Bureau radar, no NAIPS, no `api.weather.bom.gov.au`.

## v2 — native grids and the rest of the picture

| Item | Why it is later |
| --- | --- |
| ECMWF Open Data GRIB, parameters `msl` and `t` at 850 hPa only, Australian window if a subset can be proved | Step 0 of the full file was 129 MB (IFS) and 85 MB (AIFS), CCSDS, 500-connection cap, 12-run rolling archive, CC BY 4.0. A decoder (eccodes) and a machine that is awake at 00:30–03:30Z. Do not multiply 129 MB by 85 steps and call it a measurement. |
| NOAA GFS 0.25° via the AWS `.idx` and a `Range` for `PRMSL` and `TMP` at 850 hPa | The f000 GRIB was 462 MB; the MSLP message inside it was about 976 KB. Public domain on the NWS disclaimer terms. NOMADS filter is the fallback, not the default. |
| Ensemble spread on a coarse grid (1°, or 0.5° once a day) | Only if the owner wants confidence shading on the chart rather than at two pins. It spends the rest of the free quota or needs Professional (€99/month) or the GRIB `enfo` files. |
| Himawari L1b from `noaa-himawari9` | Full-disk segments were 4–8 MB each, many per scan, attribution requested by NOAA and JMA. A processor project, not a pull. |
| Upper wind on the national grid | v0 already stores 850/700/500/300 at the aerodromes. Putting those levels on the 1,836-point grid crosses the 10-variable plateau and multiplies the grid. |
| Bureau radar, only with a written yes from the Bureau | The FTP guide and the July 2026 copyright page disagree. |
| Always-on host | When v2 GRIB starts, or when v0/v1 sleep gaps are the thing `status.json` complains about. GitHub Actions is not the Bureau archive and is not the disk Isobar reads. |

## Explicit non-goals

- A public website or an API server.
- A legal flight briefing: NOTAM, NAIPS, alternate minima, a chosen runway, or the US `fltCat` flag.
- Redistributing Bureau FTP files, charts, or observations.
- Presenting Open-Meteo, NOAA, or RainViewer output as a Bureau product. The popover already shows Bureau chart images as the Bureau’s. Model grids drawn by Isobar need the Open-Meteo (and later ECMWF) credit beside them. The sea-level series is not a Bureau tide table.
- Using `ecmwf_aifs025` without `_single`, or Open-Meteo’s ACCESS models, until their meta timestamps are current. AIFS single and AIFS ensemble did return data and can be a later alternate to IFS, not a v0 dependency.
